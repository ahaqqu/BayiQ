# ADR-008: Schedule data placement — dose map in contracts, full schedule in web

**Status:** accepted  
**Date:** 2026-08-09

## Context

ADR-002 made the IDAI 2024 schedule static configuration with stable `doseId`s, and ADR-005 externalized user-facing copy into build-time JSON locale files. The spec requires the `doseId` mapping to live in "a single source file shared by web and contracts", and the full schedule to compile into `apps/web`. The prototype keeps bilingual vaccine names and explanations as data in `js/data.js`.

## Decision

- The canonical **dose map** — `doseId` → `{ vaccineId, months, code, repeat }` — lives in `packages/contracts/src/schedule.ts` and is exported from `@app/contracts`. Both `apps/web` and `apps/api` import it from there. This is the single source of truth for dose identity.
- The **full schedule** — Vaccines with bilingual `name`/`prevents`, colors, and ordered dose references — lives in `apps/web/src/lib/schedule.ts` as typed static data, compiled from the prototype.
- Vaccine names and explanations are **domain data, not UI copy**: they stay in the schedule module as `{ id, en }` pairs. Only UI chrome (buttons, labels, statuses, empty states) goes into the locale JSON files.

## Rationale

- One shared dose map prevents drift between client rendering and server validation of `doseId`s.
- The full schedule is configuration, not chrome; splitting a vaccine's name across two files would make the schedule unreadable and the locale files bloated.
- ADR-005's "no hardcoded copy" targets UI strings; schedule data is versioned with the app (ADR-002) and never changes per user.

## Consequences

- `packages/contracts` gains a non-wire module (`schedule.ts`); it is exported for web/api use but is not part of any request/response schema.
- Adding a vaccine or dose requires editing `packages/contracts/src/schedule.ts` and `apps/web/src/lib/schedule.ts` together; a `doseId`-consistency test guards the pair.
- The server may validate that a `doseId` is well-formed, but must not reject unknown `doseId`s (records must survive schedule changes — ADR-002).
