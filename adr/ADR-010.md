# ADR-010: Production custom domain — declared in `wrangler.toml`

**Status:** accepted  
**Date:** 2026-10-29

## Context

`https://bayiq.ahaqqu.com/` returned HTTP 522 for every path while the Worker answered 200 on `https://bayiq.rumaq.workers.dev/`. The `ahaqqu.com` zone was active in the same Cloudflare account as the Worker, had no Worker Routes, and had no Custom Domain for `bayiq`. The hostname was therefore served by a manually created proxied DNS record pointing at an origin that no longer answered: Cloudflare timed out connecting to it and returned 522 before the Worker was ever consulted. The repository contained no reference to `ahaqqu.com`, so no deploy could have corrected the mapping.

## Decision

- Declare the production hostname in `apps/api/wrangler.toml` as a **Custom Domain**: `[[routes]]` with `pattern = "bayiq.ahaqqu.com"` and `custom_domain = true`.
- Keep the existing `*.workers.dev` route; it serves the same Worker and remains the staging host.
- Point the `PROD_URL` GitHub variable at the custom domain so post-deploy smoke tests exercise the canonical URL.

## Rationale

- A Custom Domain is Cloudflare-managed: the DNS record and certificate are created and owned by the Worker binding, so they cannot decay into "some stale record nobody remembers".
- A manual proxied CNAME to `*.workers.dev` — or a proxied `A` record to a retired origin — is exactly the configuration that produces 522, because the edge tries to connect to that origin instead of invoking the Worker.
- Declaring the hostname in config makes the mapping reviewable and reproducible, matching how the rest of the zone is run (`rumaq.ahaqqu.com` is already a Worker Custom Domain).

## Consequences

- The deploy token needs **Workers Routes:Edit** in addition to Workers Scripts:Edit; without it `wrangler deploy` fails at the custom-domain step.
- The `ahaqqu.com` zone must stay in the same Cloudflare account as the Worker.
- Attaching a Custom Domain requires deleting any pre-existing DNS record for the hostname first (Cloudflare error `100117`); the API will not replace it.
- `PROD_URL` doubles as a regression check: if the hostname mapping breaks again, the deploy smoke test fails.
