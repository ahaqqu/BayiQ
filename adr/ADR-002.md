# ADR-002: Static IDAI 2024 schedule with stable Dose IDs

**Status:** accepted  
**Date:** 2026-08-09

## Context

The prototype encodes the 18×26 IDAI 2024 schedule in `js/data.js` and keys records by `vaccineId:months`. If we later change a dose month, existing records point to the wrong cell.

## Decision

Treat the schedule as static application configuration, versioned with `SCHEMA_VERSION`. Assign every canonical dose a stable `doseId` (e.g. `hepb-birth`, `dpt-2mo`). Records reference `doseId`; the schedule maps each `doseId` to its vaccine and months.

## Rationale

- The schedule is a universal reference, not user-generated data.
- Stable IDs future-proof schedule tweaks, catch-up logic, and local-first merges.
- Keeps the sync payload small: only records and tombstones travel, not the schedule.

## Consequences

- Schedule updates require a new app version, not a server-side change.
- We must maintain a clear mapping from `doseId` → vaccine + months in a typed source file.
- Catch-up or national-program variations will need a future ADR.
