# ADR-005: Build-time JSON i18n files

**Status:** accepted  
**Date:** 2026-08-09

## Context

The prototype keeps all `id`/`en` strings in a single `js/data.js` object. The architecture calls for localized, build-time copy and Intl formatting.

## Decision

Store translations as JSON files under `apps/web/public/locales/{id,en}.json`. The i18n layer loads the active locale once at bootstrap. Strings are externalized for both languages; no user-facing copy is hardcoded outside these files.

## Rationale

- Keeps the bundle lean and lets us lazy-load locales by route later.
- Aligns with the architecture principle that user-facing strings must be externalized.
- Intl API handles dates, numbers, and relative age formatting.

## Consequences

- Every new UI string requires both `id` and `en` entries before merge.
- Adding a third locale later is a data-only change.
