# ADR-001: Anonymous D1 sessions first, defer real OAuth/email auth

**Status:** accepted  
**Date:** 2026-08-09

## Context

The prototype has a mock auth screen (Google button + email/password) but stores credentials in `localStorage`. The real app needs an auth seam that works offline and fits the Cloudflare free-tier architecture.

## Decision

Use anonymous D1 Bearer sessions for the first real app. A one-tap “Continue” button creates or resumes a session token stored in D1. Real Google OAuth, email/password, and Better Auth integration are explicitly deferred to a later milestone.

## Rationale

- Matches the template architecture (anonymous sessions in D1, no custom crypto).
- Keeps the first vertical slice focused on immunization flows.
- Avoids managing OAuth client secrets and email deliverability in the critical path.
- Better Auth is the documented upgrade path, so the migration is foreseen.

## Consequences

- A user cannot recover data if they lose their device/session token before real auth is added.
- We must store a `userId` with local data so future account linking can merge records.
- Auth-related UI copy must be honest: “continue anonymously”, not “Continue with Google”.
