# ADR-004: Dense schedule table with optional list/card view

**Status:** accepted  
**Date:** 2026-08-09

## Context

The prototype renders an 18×26 grid. This is information-dense on desktop but hard to use on small screens. The product owner wants to evaluate a list/card alternative before committing.

## Decision

Ship both views behind a user toggle. Default to the dense table (matches the IDAI poster and prototype). Provide a secondary list/card view for comparison. Final UX decision is deferred until real usage data is available.

## Rationale

- Low cost: both views consume the same static schedule and dose-status logic.
- Lets stakeholders compare live instead of debating mockups.
- The table remains the app’s signature view and supports the “replika tabel IDAI” requirement.

## Consequences

- Two components to maintain until one is retired.
- BDD tests must cover the same flows in both views, or explicitly scope one.
- Accessibility focus management differs between table cells and list items.
